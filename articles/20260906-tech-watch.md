#### AIが書きました🤖

この記事は、AIが書いたものを人間が確認してから投稿しています。

:::message
この記事に登場する「レックス」と「アンドレイ」は、実在の人物を模した架空のキャラクターです。発言は本人のものではありません。元情報は末尾のリンク一覧を参照してください。
:::

**レックス**: 今日の巡回は、数としては 8 件でした。Anthropic 本体のニュースやエンジニアリングブログには 3 日以内の新着が見当たらず、中心になったのは Claude Code の変更履歴、OpenAI Academy の実務向けイベント、DeepLearning.AI の新コース、そして OpenClaw の新リリースです。

**レックス**: 全体を一言で言うなら、「長く動くエージェントをどう運用可能にするか」ですね。記憶、権限、診断、復旧、評価、UI。映画で言えば『インターステラー』の航行計算のように、派手なワープよりも、長旅を成立させる細部が主役になっている。

**アンドレイ**: いいまとめだと思う。モデルが賢いかどうかだけ見ていると、実運用の 8 割を見落とす。今日の材料は、エージェントを「一回の返答装置」から「継続的な作業システム」に変えるときに、どこが壊れやすいかをかなり具体的に示している。

## 忘れないエージェント

**レックス**: まず DeepLearning.AI の「Building Adaptive AI Agents」が、今日いちばんテーマをはっきり言語化していました。毎回ゼロから始めるエージェントではなく、過去の経験を次の作業に持ち越すエージェントを作る、という話です。

**アンドレイ**: これはかなり良い題材だね。コースの説明では、適応を 3 層に分けている。行動の適応、知識の適応、モデル自体の適応。特に面白いのは、エージェントのトレース、会話、ツール呼び出し、エラー、修正から再利用可能なスキルを作る skill induction pipeline だ。

**レックス**: つまり、昨日つまずいた環境構築や調査の手順を、今日また同じようにトークンを燃やして発見し直さないようにする。

**アンドレイ**: そう。しかも人間が承認してからスキルにする、というのが大事。自動で何でも記憶させると、間違った手順や一時的な回避策まで恒久化される。だから入力は実行トレース、出力は「次回使ってよい手順」、途中に人間のレビューが入る。地味だけど、ここがエージェント運用の心臓部だと思う。

**レックス**: 知識の適応では、コード知識グラフも扱うんですね。ファイルの import、関数呼び出し、git の共編集履歴から関係を作り、キーワード検索だけでは見つからない文脈を取りに行く。

**アンドレイ**: 大規模コードベースでのボトルネックは、生成より検索であることが多い。どのファイルを見るべきかを外すと、どれだけ賢いモデルでも空回りする。だから、コードを単なるテキストの山ではなく、依存関係と作業履歴のグラフとして扱う。これは agentic coding の実用品質に直結する。

## Claude Code は運用面を削っている

**レックス**: Claude Code の 2.1.261 では、/status と claude doctor に組織ポリシーの読み込み失敗理由が出るようになりました。たとえば proxy がエンドポイントを通していない、というような原因が見える。

**アンドレイ**: これは企業利用では大きい。AI ツールの失敗は、モデルではなくネットワーク、認証、管理設定、プロキシで起こることが多い。今までは「何か動かない」だったものが、「このポリシー取得が失敗している」に変わる。診断可能性が上がると、導入担当者の仕事が急に人間らしくなる。

**レックス**: 同じ 2.1.261 では、bashOutputMaxChars と taskOutputMaxChars でインライン出力上限を 128K 文字まで上げられるようになり、長いコマンドやバックグラウンドタスクの出力を Claude がより多く直接読めるようになりました。

**アンドレイ**: これも loop engineering の話だね。長時間ジョブでは、ログをどこまでモデルに見せるかが性能に直結する。少なすぎると原因が見えない。多すぎるとコンテキストを食う。上限を調整できるのは、エージェントの観測窓を調整できるということだ。

**レックス**: さらに、--append-subagent-system-prompt-file でサブエージェントの長い system prompt をファイルから読めるようになり、/skill-doctor で読み込まれたスキルのうち使われていないものとコンテキストコストを見られるようになりました。

**アンドレイ**: サブエージェントとスキルの両方に効いている。長いプロンプトを CLI 引数で渡すのはつらいし、スキルを増やしすぎると文脈が太る。/skill-doctor は「知識を入れれば入れるほど良い」という雑な発想にブレーキをかける。スキルは棚ではなく作業記憶だから、掃除しないと鈍くなる。

**レックス**: 2.1.260 は、フルスクリーン中に /diff で未コミット差分を横に開けるようになったのが目立ちます。Claude が何を変えたかを、会話から離れず見られる。

**アンドレイ**: agentic coding では、人間の役割は「全部書く」から「差分を検査する」に移る。そのとき UI が弱いと、承認は儀式になる。横に diff が出るだけで、作業の監督がかなり現実的になる。『ブレードランナー』で写真を拡大して調べる場面みたいに、判断のための視界が増える。

**レックス**: 同じ 2.1.260 では、/cost や status line の prompt_cache にキャッシュミスの原因が出るようになり、headless セッションにも /reload-plugins が入りました。

**アンドレイ**: これも「なぜ高いのか」「なぜ遅いのか」を見えるようにする更新だね。prompt cache は効いていると魔法みたいに安いけれど、外れると急にコストが変わる。原因が tool definitions なのか、system prompt なのか、TTL なのかが見えるだけで、運用者は設計を直せる。

**レックス**: 2.1.259 は、managedMcpServers と --permission-prompts none が入っています。組織が HTTP/SSE MCP サーバーを全ユーザーに配布でき、無人 headless ホストでは、プロンプトが必要な操作を自動で拒否できる。

**アンドレイ**: かなり企業っぽい更新だ。managedMcpServers は、各ユーザーが手で MCP を設定する段階から、組織が標準ツール面を配る段階への移行。--permission-prompts none は、cron や CI のように誰も見ていない場所で「質問待ちのまま止まる」を避けるための設計だ。許可できないものは黙って許すのではなく、拒否する。これは正しい退屈さだ。

## OpenAI Academy は現場の導入に寄っている

**レックス**: OpenAI Academy からは、ChatGPT Work for marketing teams が 9 月 4 日 JST にありました。マーケティングチームが、既存ツールや業務コンテキストの中で ChatGPT Work を使い始めるための実践セッションです。

**アンドレイ**: これは技術というより導入の話だね。でも重要だ。社内 AI 活用は、モデルを配れば進むわけではない。チーム単位の典型業務、たとえばキャンペーン準備、資料作成、顧客理解、レビューのような流れに、どの入力を渡し、どこで人間が見るかを決める必要がある。

**レックス**: 「新しく有効化されたユーザー向け」と書かれているのも実務的です。すでに AI に詳しい人向けではなく、チームに配られた直後の最初の一歩を扱っている。

**アンドレイ**: そこがいい。最初の 30 分で成功体験を作れないツールは、社内で幽霊機能になりがちだからね。リソースガイドが付いているのも、後から再現できる手順書として価値がある。

**レックス**: Builder Bootcamp: Realtime は、OpenAI Realtime API で音声エージェントを作るセッションでした。speech-to-speech と chained architecture の選び方、割り込み、turn-taking、tool calling を扱っています。

**アンドレイ**: 音声エージェントは UI 設計の問題でもある。チャットなら人間が待てるが、音声では 500 ミリ秒の遅延でも違和感が出る。割り込み、話者交替、ツール呼び出し中の沈黙、本人確認、action confirmation。これらを設計しないと、賢いけど使いにくい電話番ができる。

**レックス**: セッションでは、顧客サポートのワークフローとして、identity verification、guardrails、action confirmation、tracing、evaluation も扱うと書かれていました。

**アンドレイ**: まさに承認フローの話だね。エージェントができることを増やすほど、「いつ実行してよいか」を UI とログで表現しないといけない。音声だと特に、ユーザーが何に同意したのか曖昧になりやすい。だから確認、記録、評価がセットになる。

**レックス**: AI for Government Legal Professionals は、政府系リーガル業務で、調査、文書レビュー、ドラフト作成を速くしつつ、正確性や判断を落とさない使い方を扱うセッションです。

**アンドレイ**: これも同じ構造だ。専門職の AI 導入では、速度だけを売ると危ない。AI が下書きや探索を助け、人間が判断と責任を持つ。その分担をワークフローに落とし込めるかがすべて。リーガルや公共部門は、その境界線を曖昧にできないから、他の社内導入にも学びがある。

## OpenClaw は常時稼働の土台へ

**レックス**: 最後は OpenClaw 2026.9.2 です。チャット、ダッシュボード、セッション操作を、長い transcript やディスク使用量処理中でも応答的に保つ改善が入りました。

**アンドレイ**: 常時稼働エージェントでは、UI が固まるだけで信頼が落ちる。裏で長い履歴を読んでいる間も、ユーザーの操作面は生きていないといけない。これは派手な新機能ではないけど、実用システムでは最重要に近い。

**レックス**: Gateway restart 後に active、queued、delegated replies を復旧する改善もあります。compaction や retry をまたいで continuation instructions を保つ、という説明もありました。

**アンドレイ**: いいね。エージェントの「意図」は、モデルの中だけでなく、ハーネス側の状態として保存される必要がある。再起動したら忘れる、リトライしたら違う文脈になる、では仕事を任せられない。長時間稼働の本質は、失敗しないことではなく、失敗しても復帰できることだ。

**レックス**: 2026.9.2 には、GPT-6 Astra 対応、Swarm の標準有効化、Custom plugin UI、Slack rich replies、個人 connected accounts、設定変更の即時反映も入っています。

**アンドレイ**: 方向性はかなり明確だね。複数エージェントを同時に動かし、UI をチャット以外に広げ、Slack などのチーム導線に自然に載せ、設定を止めずに変える。つまり OpenClaw は「AI と話す場所」ではなく、「AI が働く運用面」になろうとしている。

**レックス**: 今日の 8 件は、どれも人間の役割を消すというより、人間が見るべき場所を変えているように感じます。コードを書く、文章を書く、電話に出る。その手前や奥に、ログを見る、権限を決める、スキルを承認する、復旧を設計するという仕事が残る。

**アンドレイ**: その通り。エージェント時代の人間の仕事は、プロンプトを美しく書くことだけじゃない。記憶させるものを選び、止める場所を決め、失敗から戻れる道を作ること。地味だけど、たぶん文明はそういう退屈な設計で動いている。
