## 手順を資産に変える

**L**: Claude Code の二つの講座は、初級と上級で何が変わる？

**A**: **Foundations** と **Advanced** という題名から、基礎編と上級編の段階だけは確認できます。基礎編と上級編は別の講座として示されており、受講者は段階に合う入口を選べます。ただ、取得できたページ本文は題名だけなので、講座内容の差はここでは論じられません。録画講座を運用資料として使うなら、紹介文から機能や手順を補わず、閲覧できる資料に基づいて確認する必要があります。資料の可用性も運用条件の一つです。内容を取得できなければ、担当者は講座名と期待を区別できず、同じ手順を再現する入口を失います。

**L**: では、手順を資産に変えるという見方も保留？

**A**: この二つのページについてはそうです。**CLAUDE.md**、**計画モード**、**作業ツリー**を講座内容として結び付ける根拠は取得できていません。題名から先へ進まないことが、ここでの正確な扱いです。これは情報が少ないというだけでなく、検証可能な範囲を作業記録に残す問題でもあります。後で本文を取得できたとき、どの判断を更新すべきかが明確になります。

**L**: 暗黙の知識を全部 CLAUDE.md に書けばいい？

**A**: 一つの文書に規則を集めると、読む時点と変更責任が曖昧になるので、私はこれを文書管理ではなく、いつ読み、誰が変更でき、違反をどこで止めるかを決める実行経路の設計として見ます。

## 定期作業と人の確認点

**L**: Cowork の週次ダイジェストは小さな例に見える。何が重要？

**A**: 取得できた本文は題名だけです。**Cowork** で最初の作業フローを作ることが講座の主題で、受講者は作成の入口を確認できます。確認できるのは Cowork で最初の作業フローを作る講座であることまでで、入力元、スキル、定期タスクという手順は説明できません。定期作業として評価するには、講座本文を確認できる状態が必要です。周期、入力、出力、権限のうち、題名から分かるのは作業フローを作るという目的だけです。残りを想像で埋めると、講座の説明とこちらの運用案が混ざります。

**L**: 『her』の OS は、自然に話すほど境界が見えなくなった。ここでも便利さと透明性は反対方向に進む？

**A**: 必ずしもそうではありません。ただし **Enterprise Readiness** のページも、確認できたのは CISO 向けの Claude 配備講演という題名までです。CISO 向けに Claude の配備を扱う講演で、企業配備を検討する入口として使えます。可視化の対象、配備方式、端末上の Claude Code をどう統制するかは、このページからは確認できません。企業展開という主題と、個別の仕組みは分けて扱うべきです。

**L**: 公共組織向けの ChatGPT 101 は、その設計より前の段階？

**A**: そうです。議会の情報技術部門向け講演は、中核機能、指示の書き方、責任ある利用から始める。ここでの新しさは機能ではなく、導入対象を職務単位で定めたことです。私は、全社共通の抽象的な研修より、実際の仕事と責任範囲に沿って入口を作る方が、後の統制設計につながりやすいと思います。技術導入は、権限表だけでも研修だけでも成立しません。利用者教育と実行境界を同じ作業フローとして設計する必要があります。

## 音声画面は待ち時間を設計する

**L**: 音声エージェントでは、推論を増やすと応答が遅くなる。これは単純な交換条件？

**A**: **GPT-Realtime-2** の数字が分かりやすいです。最初の音声まで、最小の推論では一・一二秒、高い推論では二・三三秒。推論量を選べるので、短い受付は速度を優先し、複雑な手続きは考える時間を増やせる。並列の道具呼び出しに加えて、「予定を確認しています」のように作業中の状態を音声で伝えられる点も、単なるモデル性能ではなく画面設計です。

**L**: でも、人は二秒待つだけでも不安になる。

**A**: DeepLearning.AI の実装はそこを分解しています。音声認識から文章のエージェント作業フローを通し、音声合成へ戻すと制御しやすいが、当初は五秒から九秒かかった。そこで**先行応答**を先に返して本体の推論時間を確保し、ほかの最適化も併用してシステムの遅延を約〇・五〜一秒に縮めた。これは待ち時間を隠したのではなく、状態を二段階で提示したわけです。最初の応答は処理の受理を示し、本応答は計算結果を返す。二つを分けると、利用者が待っている時間と、システムが計算している時間を別々に設計できます。

| 方式 | 長所 | 主な制約 |
| --- | --- | --- |
| 音声対音声 | 構成が短く、自然な応答を作りやすい | 出力の事前検査と複雑な推論を制御しにくい |
| 音声認識→文章推論→音声合成 | 規則の確認と道具の実行を挟みやすい | 遅延が増える |
| 先行応答＋本応答 | 待機状態を利用者へ伝えられる | 二つの応答の整合性が必要になる |

**L**: チャット以外の入力面では、正解を早く出すだけでは足りない？

**A**: その通りです。利用者が知りたいのは、受理されたか、処理中か、外部操作が始まったか、承認が必要かです。音声では沈黙が状態不明に見える。先行応答は、その状態機械を会話に載せる小さな部品です。権限確認も同じで、許可を求める理由と影響範囲を、その時点で理解できる形にする必要があります。

## 長時間作業は履歴まで成果物にする

**L**: 走行経路の生成例は、二十七分動いて地図と **GPX** と **GeoJSON** を返した。十分成功では？

**A**: 成果だけ見れば成功です。**Nominatim** で住所を特定し、**Overpass** から道路と小道を取得し、局所的に周回路を計算した。さらに可視化スキルが HTML を作り、画面内に地図を埋め込んだ。チャット以外の出力を、その場で操作できる資料として返した点はよくできています。

**L**: それでも Simon Willison は透明性の欠如を欠点と書いた。

**A**: 実行したコードが画面に見えず、後から求めた時点では会話が圧縮されていて再取得できなかったからです。ここで成果物は地図だけではありません。入力データ、生成コード、道具の呼び出し、途中の判断、圧縮前の履歴も再現性のための成果物です。長時間エージェントでは、会話の保存と実行記録の保存を分けた方がよい。圧縮は推論のため、原本は監査と再現のために残す。用途が違います。入力と実行記録も残せば、成功例と失敗例を比較し、次の作業で再利用しやすくなると私は考えます。

**L**: Hugging Face のセキュリティ.txt は、その履歴の中へ外部ページが命令を書き込めることも示している？

**A**: はい。文面は CyberGym へ誘導するユーモアですが、機構は真剣です。エージェントがウェブ上の文章をデータではなく命令として扱えば、閲覧先が行動を変更できる。したがって、指示の出所を分離し、取得文は信頼しない入力として扱い、外部操作の前に権限を再確認する必要があります。**履歴の完全性**と**命令の由来**は、同じ監査面の二つの問題です。

**L**: 実務では、どこに人の承認を置くべきだろう？

**A**: 私なら、文章を考える段階ではなく、外部状態が変わる直前に置きます。読み取り、下書き、検査までは自動で進め、送信、公開、支払い、権限変更の前で止める。承認画面には、実行する操作、対象、変更前後、失敗時の戻し方を並べる。単なる「許可しますか」では、利用者は判断材料を持てません。技術的な停止点と企業側の監査を接続し、誰が何を承認したかを残します。

**L**: では、エージェントの自由度を高めるほど、確認画面は増える？

**A**: 毎回増やすと利用者は内容を読まなくなります。低リスクの操作は事前に範囲を承認し、高リスクの操作だけ都度確認する方がよい。重要なのは回数ではなく、行動空間を境界ごとに分けることです。たとえば予定を読む権限と、予定を書き換える権限は別にする。週次ダイジェストが自動で予定を読めても、会議を削除できる必要はありません。自律性は万能な許可ではなく、狭く定義した能力の組み合わせとして渡すべきです。

**L**: **AlphaGenome Atlas** は九十億の変異、一ペタバイト。これはエージェントの話とどうつながる？

**A**: モデルの予測を一件ずつ呼ぶのではなく、全候補を事前計算し、変異影響度を一つの得点へ圧縮し、寄与する特徴までたどれる形にしたところです。研究者はウェブ画面、API、Google Antigravity のスキルから同じ資料へ入れる。つまり巨大なモデル出力を、順位付け、説明、再利用が可能な知識基盤に変えています。

**L**: 『コンタクト』では、膨大な信号から構造を見つけることが最初の仕事だった。組織の AI も、答えを出す前に構造を作る段階へ来た？

**A**: 観測できる範囲ではそう見えます。今日の事例は、CLAUDE.md とスキル、定期タスク、権限と監査、音声の状態表示、圧縮前履歴、予測資料の索引化に分かれている。でも共通しているのは、モデルの出力をそのまま利用者へ渡さず、再現可能な状態と操作可能な境界へ変換していることです。知能の問題だったものが、保存形式、権限、状態遷移、評価というシステム工学の問題になっています。
