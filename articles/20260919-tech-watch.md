## 評価を内側へ、権限を外側へ

**L**: 評価者に従業員相当のアクセスを与える一方で、実行するモデルには本物の認証情報を渡さない。向きは逆だけれど、どちらも境界の置き方を変えている。安全性はモデルを賢くする問題ではなく、誰をどこまで内側へ入れるかという問題になったのかな。

**A**: AnthropicとAccenture傘下Facultyの提携で新しいのは、レッドチーム、アラインメント評価、安全策の試験を、外から完成品に当てるのではなくAI企業の内部で行う点です。評価者が従業員相当のアクセスを持てば、公開後の挙動だけでなく、開発中の仕組みに近い位置で検査できる。少なくとも計画の規模はこうです。

| 当事者 | 予定する投資 |
|---|---:|
| Anthropic | 5年で少なくとも10億ドル |
| Accenture | 5年で少なくとも10億ドル |

ただし、アクセスが深いことと評価が独立していることは同じではない。資金の流れと報告基準がまだ確立していないなら、ここでできるようになるのは「内部で評価すること」であって、「結果の信頼性が自動的に保証されること」ではありません。評価対象への距離は縮まった。次は評価者を誰が評価するかという運用の問題が残る。

**L**: 『マトリックス』では、内部に入るほど世界を操作できる。でも現実の安全設計では、内部へ入る主体を増やすほど監督の線も増える。Museの分離は、その複雑さをどこで止めている？

**A**: Meta Museは逆側から境界を引いています。仮想マシン内を、信頼できないデータを扱うセルと外部サービスに接続する部分へ分離する。モデルが持つのは代替トークンで、外側のSentinelが要求された権限を検査し、通す場合だけ本物の認証情報へ交換する。入力が要求に変わり、境界で検査され、許可された操作だけが外へ出る。仕組みが一段下まで見える、よくできた設計です。

送信や購入は常に確認し、承認は会話の外にあるシステム画面で取る。ここが重要です。会話内の文字列は、利用者の指示も信頼できないデータも同じ入力列に入る。承認画面まで会話に置けば、モデルが読む文章と人が決定する画面の境界が曖昧になる。できるようになるのは、エージェントに外部サービスを使わせながら、実認証情報と最終決定をモデルの外へ保つことです。エージェントの安全性を、従順さではなく能力の分離として扱っている。

## フォルダから継続する作業空間へ

**L**: Claude Projectsは、資料を置くフォルダから会話を束ねる場所へ変わった。さらにClaude CodeはAGENTS.mdを読めるようになった。自然言語がプログラムなら、プロジェクトの指示ファイルは設定ファイルに近づいている？

**A**: Claude Projectsの変更で新しいのは、一つの目標を複数のClaudeセッションへ分け、ログオフ後も継続させ、複数のコーディングセッションを並行管理できる点です。フォルダは静的な資料の境界だった。再設計後は、目標があり、その下で複数の実行が進む。できるようになるのは、利用者が一つの会話を開いたまま待つのではなく、仕事を分割して戻ってくることです。まだベータなので、ここでは継続と並行管理が提供されたことまでを見ればよい。

これをSoftware 3.0として見ると、指示の置き場所が製品の操作体系になります。Claude Code 2.1.277は、CLAUDE.mdがないフォルダでAGENTS.mdを読む。Project instructionsで切り替えられるので、同じリポジトリでも、どの指示規約を入口にするか選べる。新しくできるのは、既にAGENTS.mdで運用しているプロジェクトを、指示の複製なしでClaude Codeにつなぐことです。

**L**: 実装が組み込みmodだという点は地味に見える。けれど将来は独自のproject instructionsを作れる予定だという。これは互換性の話なのか、拡張機構の話なのか。

**A**: 現時点の事実だけなら両方の入口です。Claude Code mods上の組み込みmodとしてAGENTS.md対応が実装され、将来は独自のプロジェクト指示を作れる予定になっている。指示ファイルの名前を本体へ一つずつ埋め込むより、読み方をmodとして差し替える方が構造は単純です。いや、利用者から見た設定項目は増えるので、単純なのは内部の責務分離ですね。

ここで一つに圧縮するなら、**会話の管理から実行の管理へ**という変化だと思います。Projectsは複数セッションを束ね、指示ファイルは各実行の振る舞いを固定する。モデルの能力が同じでも、目標、指示、実行単位の配置が変われば扱える仕事の長さが変わる。10年前なら人がスクリプトとジョブ管理で組んだ部分に、今は自然言語の指示とセッション管理が入っている。製品化で難しいのは、デモを作ることより、再開や並行実行を壊さずmarch of ninesを進めることです。

## 記憶は増量ではなく選択

**L**: Proactive Memoryは、行動するエージェントとは別にメモリエージェントを走らせる。『her』のような一つの人格が全部を覚える像より、裏で資料係が必要な項目を差し出す構図に近い。なぜ分けると改善するのだろう。

**A**: 報告された数字から入ると、Claude Sonnet 4.5の成功率は次のように変わっています。

| 評価 | 導入前 | 導入後 |
|---|---:|---:|
| Terminal-Bench 2.0 | 37.6% | 45.9% |
| τ2-Bench | 55.0% | 61.8% |

提案の核は、行動エージェントが作業している横で、別のメモリエージェントが関連情報を選び、必要な時点で提示することです。できるようになるのは、行動側が目の前の操作を続けながら、過去の情報を別系統で拾うことです。コンテキストウィンドウへ何でも詰める方式では、重要な情報と雑音が同じ場所を奪い合う。別の主体に選択を任せると、記憶容量の問題を検索と提示の問題へ変えられる。これは**記憶の増量から記憶の配膳へ**という設計変更に見えます。

**L**: でも、配膳する側が間違えば、行動側は正しい情報を思い出せない。理解を外へ預ける問題は、人間がLLMで文章を書くときにも同じではないか。

**A**: そこがThomas Ptacekの規則とつながります。新しい道具を発明したというより、LLMの役割を代筆者から校正者へ狭めたことが明確です。モデルが提案した言い回しをそのまま採用しない。Simon Willisonも、事実確認、綴りと文法の確認、類語探しを用途に挙げている。できるようになるのは、自分の主張と文体を保持したまま、検査や探索だけをモデルに分担させることです。

文章でもエージェントでも、外部の補助系は候補を出せるが、何を採用したかの責任までは移せない。私は「思考を外注するな」とまでは言いません。事実確認や類語検索は外へ出せる。ただし、なぜその文を置くのかを説明できなければ、書き手の理解は増えていない。校正者が原稿を全部書き直したら、それは便利な校正者というより、職務範囲を広く解釈する同僚です。会社ではたまにいます。

## 専門組織、小規模モデル、巨大基盤

**L**: 残る三件は規模がばらばらだ。Sakana AIは研究組織を作り、Liquid AIとInsilico Medicineは老化指標を読む小規模モデルを出し、Z.aiは10万チップ規模の推論基盤を語る。同じ競争の別の層なのかな。

**A**: まず、確認できた主張を混ぜない方がよいです。Sakana AIが9月18日に発表したFrontier Intelligence Groupは、フロンティア級の知能研究を専門組織として進めるための組織設計です。新しいのは研究テーマではなく、専門組織を置いたこと。できるようになるのは、その目的に人と活動をまとめることです。成果はまだここから読み足せません。

LongevityBenchでは、Liquid AIとInsilico Medicineが、血中タンパク質やDNAマーカーなどの老化指標を読む小規模モデルと評価を発表した。両社はGPT-5、Gemini、Claudeを上回ると報告しています。ただし評価条件は今回の確認範囲にないので、比較結果は両社の主張として扱うべきです。新しいのは、老化指標を対象にした小規模モデルと評価を一緒に出したこと。できるようになるのは、その対象について専用モデルを評価することです。

**L**: Z.aiの発表はさらに大きい。GLM-5.3が後継の推論基盤構築を支援したという。自分の次の計算機を作るAIという言い方は魅力的だけれど、どこまで具体化できる？

**A**: 確認できる範囲は、Z.aiがGLM-5.3について、10万チップ規模の推論基盤構築を支援したと発表したところまでです。新しいのは、AIが利用される側だけでなく、後継AI基盤の構築工程へ入ったと位置付けられていること。できるようになるのは、少なくとも同社の発表上、基盤構築の作業にモデルを参加させることです。どの工程をどの程度担ったかは足さない方がよい。

三件を同じ層に押し込む必要はありません。組織は研究する人の配置、専用モデルは対象と評価の対応、推論基盤は計算資源と構築工程の話です。ただ、どれもモデル単体の順位だけでは説明できない。誰を集めるか、何を測るか、どの計算基盤で動かすかが能力の外周を決める。知能の問題に見えて、かなりの部分が実行の問題です。

**L**: OpenAI AcademyのHoustonでの対面イベントは、その大きな流れの末端にあるのかもしれない。小規模事業者がChatGPTを業務で使う話で、日本からライブ視聴する催しではない。それでも、基盤競争と同じ日に見る意味はある？

**A**: あります。ただし短く見れば十分です。9月21日9:30〜13:30 CDTにHoustonで開かれ、小規模事業者向けにChatGPTの業務利用を扱う。新しい研究発表ではなく、できるようになるのは現地の参加者が業務利用を学ぶことです。10万チップの基盤も、最後は誰かの具体的な作業へ接続される。そこまで降りなければ、巨大な計算資源は利用者にとってただの遠い設備です。

**L**: 今日の話では、評価者、人の承認、指示ファイル、メモリエージェント、専門組織がモデルの周囲に増えていた。人間はAIの外側で境界を引き続ける役になるのだろうか。最後に残る仕事は何だろう。

**A**: 今見えている範囲では、残るのは境界を定義して検証する仕事です。モデルが何を知っているかだけでなく、誰が内部を評価できるか、どの権限を渡すか、どの記憶を提示するか、どの指示を読むか、結果を何で測るかを決める。モデルが強くなるほど、この外周は小さくならず、むしろシステムとして明示される。人間の役割を抽象語で決める必要はなく、まず承認画面、評価基準、作業の分割という観測できる機構に置けばよいと思います。
