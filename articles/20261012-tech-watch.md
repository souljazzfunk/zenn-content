## 権限確認を会話から境界へ移す

**A**: Claude Code の四つの更新を並べると、モデルの賢さではなく、**権限判定の状態管理**を直している。2.1.289 で新しいのは、複合シェル命令の内側や環境変数の代入後にある命令にも拒否・確認規則を保つことだ。これで、表面の文字列を少し変えただけで管理対象の操作が規則をすり抜ける経路を塞げる。

**L**: 一つの命令を許可したつもりが、連結された後半まで許可されるのは境界の置き方が違う。文字列ではなく、実行される操作を見なければならないということ？

**A**: そう思う。さらに2.1.294 は、自然言語で書いたフックが「拒否すべきものを許可する」反転を修正した。Stop と SubagentStop でも、「ビルドが壊れていれば続ける」のような指示をより正しく判定する。新しくできるのは、フックを短い方針文で書きながら、危険な操作を止め、未完了なら作業を続けるという二種類の制御を任せることだ。

**L**: でも自然言語の判定は確率的だ。組織の規則をそこへ重ねるなら、誰の操作かも重要になる。

**A**: そこで2.1.290 の agentId と ceiling が意味を持つ。前者は主セッションとサブエージェントのどちらが道具を呼ぼうとしているかをフックへ渡し、後者は組織が要求する承認水準を質問と判定へ渡す。これにより、たとえば主セッションには許す操作をサブエージェントには確認させ、組織の上限を局所設定で下げない権限設計ができる。

**A**: 同じ版は、圧縮後に消えていた定期タスクの再開、長い WebFetch の続きの取得、再開したサブエージェントの思考とプロンプトキャッシュ保持も直した。2.1.291 はその直後に、クラウドセッションで権限確認の回答が落ちる回帰と、終了時に最後のメッセージが失われる回帰を修正した。できるようになるのは、承認待ちを挟む長時間処理を再開し、最後の判断と結果を履歴に残す運用だ。

**L**: 安全装置が増えたというより、停止、承認、再開の遷移を一つずつ修理している。華やかな機能ではないけれど、無人実行はこの遷移が欠けると成立しないね。

**A**: まさに実行の問題だ。短い実演なら成功率九割でもよいが、毎日回すなら失敗率の桁を一つずつ下げる作業が必要になる。権限画面への回答を一度失うだけでも、長い仕事全体が止まる。自律性はモデルの能力ではなく、状態機械の信頼性まで含む。

## ハーネスは本番運用の小さな制御系

**L**: Codex の講座が、権限、サンドボックス、サブエージェント、メモリを一緒に扱うのは象徴的だ。個別機能の説明ではなく、周囲をどう組むかが主題になっている。

**A**: Codex の上級自動化講座で新しいのは、Codex を対話型の補助から、本番の自動化へ広げる実践パターンを一つの録画セッションにまとめたことだ。書き込み可能なルート、実行規則、計画モード、Codex SDK と非対話実行まで扱う。これで、継続的インテグレーション、セキュリティ検査、コードレビューの作業フローに、制約付きのコーディングエージェントを組み込める。

**L**: そもそも**ハーネス**は何をするもの？

**A**: 入力を受け、使える道具と書ける場所を狭め、途中結果を保存し、失敗時に止め、必要な地点だけ人へ戻す外側の制御系だ。モデルを交換しても境界と検証を残せるのが重要になる。いや、「外側」は少し不正確だ。モデルへ渡すコンテキストも含むので、実際にはモデルを包む実行環境に近い。

**A**: Simon Willison の例は、その最小形になっている。新しいのは、ChatGPT に Python 配布用リポジトリを毎時更新させ、安定版 Python 3.15 の追加を見つけた時点で通知させたことだ。これにより、人が数時間おきに確認しなくても、条件が成立するまで安価な確認を繰り返し、GitHub Actions のテスト行列へ追加できる時点を知れる。

**L**: 大きな「自律エージェント」より、終了条件の明確な監視の方が先に日常へ入るのかもしれない。自由度が低いから、正否も確認しやすい。

**A**: その見方に賛成だ。検証可能性が高い。リポジトリに該当変更があるかは機械的に確かめられ、通知後の行動は人が選べる。長時間稼働という言葉から無制限な自由を想像しがちだが、実用になるのは、狭い行動空間と明確な終了条件を持つループからだと思う。

## 道具は単品ではなく集合で選ぶ

**L**: 道具が数千個あると、モデルへ全部の説明を渡すだけでコンテキストを使い切る。検索で上位を選べばよさそうだけれど、航空券の道具ばかり並んだら、ホテルも天気も調べられない。

**A**: The Batch が紹介した方式の名前は **HYSET** だ。新しい点は、各道具をタスクとの近さだけで独立採点せず、道具同士の相性と、集合全体が依頼をどれだけ覆うかを合わせて採点することにある。学習時には正しい集合だけでなく、無関係な集合や、一、二個を入れ替えた難しい誤答も比較する。

**A**: 実行時は、依頼との一致度が高い候補と、それらとの相性が高い候補から短い一覧を作り、部分集合を再順位付けする。これにより、基礎のエージェントを変更せず、必要な道具が一式そろう確率とタスク完了率を上げられる。個別の名選手を集めるより、五人で必要な役割を埋める方を見る。仕組みとしてはきれいだ。

**L**: これはモデルに道具を教える問題というより、呼び出せる能力をその都度編成する問題だね。権限設計ともつながる？

**A**: つながる。選択器が候補を絞れば、権限審査の対象も小さくできる。ただし、選ばれた集合が安全だとは限らない。検索は「仕事を完了できるか」を最適化し、権限層は「許された範囲か」を判定する。この二つを同じ得点へ混ぜず、直列の境界として置く方が監査しやすい。

## 安価な知能、長い出力、物理的な行動

**L**: GPT-6.1 Sol、Gemini 4 Argon、FLUX 3 Action は別の方向に見える。共通しているのは、能力を一回の回答ではなく、長い仕事へ接続しようとしている点だろうか。

**A**: GPT-6.1 Sol で新しいのは、Artificial Analysis の総合指標で GPT-6 Astra と一点差の性能を、同指標の一タスク当たりでは四分の一未満の費用で出したことだ。Codex 上のコーディング評価では Astra を一点上回り、費用は一五パーセント未満だった。これで、多段のコーディングやコンピューター操作を、高価な最上位モデルだけに頼らず大量に回せる。

**A**: ただし、常時稼働エージェント Dots には同等の外部評価がまだない。四千超のアプリへ接続し、承認規則に従って動くなら、モデル得点より接続先、権限、監査の評価が必要になる。安くなれば試行回数が増えるので、周囲の境界が受ける負荷も増える。

**L**: Gemini 4 Argon は最大一〇〇万トークンを出力できる。長さそのものより、途中で止めて次の呼び出しから継続する仕組みが気になった。

**A**: そこが新しい。Long Decode Continuation で長い応答を中断・再開し、内部活性をプローブで監視し、間接プロンプト注入への合成攻撃で訓練する。これにより、法務や金融の長い文書、あるいは大規模なコード移行を途中で時間切れにせず進め、逸脱時には監視系が停止できる。Google は Fuchsia の C と C++ のコード八〇万行超を Rust へ移した例を挙げている。

**L**: 「分からない」と答える割合も能力の一部になる。法務や金融では、もっともらしい誤答より拒否の方が人へ戻しやすい。

**A**: そう。誤答を罰し拒否を罰しない評価で、Argon の誤答率は同水準の上位モデルより低かった。これは知識量だけではなく、**委譲可能な失敗**の設計だ。拒否を別のモデルか人へ送る経路まで作れば、誤りを黙って通すより扱いやすい。

**L**: FLUX 3 Action は、その長い仕事を物理世界へ持ち出す。映像を作るモデルが、なぜロボットを動かせるの？

**A**: 新しいのは、カメラ画像、文章の指示、関節位置から、次の動作とその結果見える映像を同時に予測する**世界行動モデル**にしたことだ。一回に約二秒分の動作を出し、最初の数動作を実行してから再び観測し、計画し直す。これにより、映像から得た物理世界の規則性を使い、約二百件の実演で低価格なロボットアームへ適応できる。

**A**: シミュレーションでは首位でも成功率は半分未満で、上位モデルは実機の共通評価にまだ出ていない。映像予測は豊富な事前学習を行動へ移せるが、食卓の摩擦や物体のずれは採点表より厳しい。できるようになったのは研究室で適応を試すことまでで、家庭へ置ける信頼性とは分けて考える必要がある。

**L**: 人間は、文章の生成器、コードを書くエージェント、動く機械に、少しずつ長い自由を渡している。最後に残る人間の役割は、承認ボタンを押すことなのかな。

**A**: 承認だけでは足りないと思う。観測できる状態を定め、許可する能力を狭め、成功条件を機械で検証し、拒否や失敗を誰へ戻すか決めることが残る。モデルが何を知っているかより、何を呼べるか、どこへ書けるか、停止後に正しく再開できるか。自律性の中心が、モデル単体から実行基盤の設計へ移っている。
